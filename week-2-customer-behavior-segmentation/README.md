# Customer Behavior Analysis & Segmentation — Working Project

A simple, working implementation of the Week 2 strategy report
`Customer Behavior Analysis and Segmentation`. Same lightweight stack
as the Week 1 project, on purpose:

- **CSV files** as the data store (`data/customers.csv`, `data/transactions.csv`)
- **Pandas** for cleaning, RFM scoring and behavioral feature engineering
- **NumPy** for the underlying calculations
- **Matplotlib** for all charts
- **Streamlit** for the interactive dashboard

No database, no clustering libraries, no real customer data — a
**simulated** dataset is generated locally, exactly as the report
recommends for a student project (Section 11 & 19).

## Setup

```bash
# 1. clone the repo
git clone https://github.com/<your-username>/customer-behavior-segmentation.git
cd customer-behavior-segmentation

# 2. create a virtual environment (optional but recommended)
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate

# 3. install dependencies
pip install -r requirements.txt

# 4. (re)generate the sample data — already included, but you can
#    regenerate a fresh simulated dataset any time
python data/generate_customer_data.py

# 5. run the dashboard
streamlit run app.py
```

Then open the URL Streamlit prints (usually `http://localhost:8501`).

## How segmentation works

1. **Feature engineering** — for each customer: recency (days since
   last completed order), frequency (order count), monetary (total
   spend), average order value, discount usage rate, return rate,
   favorite category, most-used device.
2. **RFM scoring** — each of Recency, Frequency and Monetary is split
   into 5 quintiles (score 1-5) across the customer base.
3. **Segment assignment** — a simple, transparent rule (`assign_segment()`
   in `src/segmentation.py`) maps R/F/M scores to one of six segments:
   **High-Value, Loyal, New, Promising, At-Risk, Inactive** — matching
   the labels used throughout the report.
4. **Behavioral layer** — category preference, device behavior,
   discount sensitivity and acquisition channel are added on top of
   the RFM segment to make each group easier to act on.

## Using your own data

Replace `data/customers.csv` and `data/transactions.csv` with real
(anonymized) exports using the same column names, and everything
downstream recalculates automatically.

## Notes

- All customer IDs and transactions are **synthetic**, generated by
  `data/generate_customer_data.py` — safe to share publicly.
- Six hidden "behavior archetypes" are used only inside the generator
  to make the simulated data realistically separable; the segmentation
  code itself never sees or uses them — segments are calculated purely
  from RFM + behavior rules, the same way it would work on real data.
- Clustering (e.g. K-Means) is intentionally left out, matching the
  report's recommendation to validate a simple RFM segmentation first
  (Section 17) before adding more complex methods.
