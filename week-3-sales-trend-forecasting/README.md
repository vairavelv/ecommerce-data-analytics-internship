# Sales Trend Forecasting & Visualization — Working Project

A simple, working implementation of the Week 3 strategy report
`Sales Trend Forecasting and Visualization`. Same lightweight stack as
Weeks 1 and 2, on purpose:

- **CSV file** as the data store (`data/transactions.csv`)
- **Pandas** for cleaning, aggregation and time-series handling
- **NumPy** for the moving-average and linear-regression calculations
  (`np.polyfit` — no scikit-learn needed for a trend line this simple)
- **Matplotlib** for every chart
- **Streamlit** for the interactive dashboard

No database, no ML frameworks — a **simulated** daily sales dataset
(with trend, yearly seasonality and a few promo spikes) is generated
locally, exactly as the report recommends for a student project.

## Setup

```bash
# 1. clone the repo
git clone https://github.com/<your-username>/sales-trend-forecasting.git
cd sales-trend-forecasting

# 2. create a virtual environment (optional but recommended)
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate

# 3. install dependencies
pip install -r requirements.txt

# 4. (re)generate the sample data — already included, but you can
#    regenerate a fresh simulated dataset any time
python data/generate_sales_data.py

# 5. run the dashboard
streamlit run app.py
```

Then open the URL Streamlit prints (usually `http://localhost:8501`).

## How forecasting works

1. **Clean & aggregate** — raw daily orders are de-duplicated, invalid/
   missing revenue is dropped, cancelled orders are excluded, and the
   result is resampled into a regular daily/weekly/monthly time series
   (chosen from the sidebar).
2. **Baseline** — forecasts the next period as equal to the last known
   period (the minimum bar any real model should beat).
3. **Moving average** — averages the trailing N periods (N is
   adjustable) and rolls that average forward for multi-period forecasts.
4. **Linear trend regression** — fits `revenue = slope × time + intercept`
   with `numpy.polyfit` and projects it forward.
5. **Evaluation** — the series is split chronologically (no shuffling);
   all three methods are backtested on the held-out tail and compared
   using MAE, RMSE and MAPE.
6. **Future forecast** — the chosen method is projected beyond the full
   historical range for a user-selected horizon.

## Using your own data

Replace `data/transactions.csv` with a real (or anonymized) order
export using the same columns — `order_id, order_date, revenue,
quantity, order_status` — and everything downstream recalculates
automatically.

## Notes

- All data is **synthetic**, generated by `data/generate_sales_data.py`
  — safe to share publicly.
- The linear trend model is intentionally simple, matching the
  report's recommendation to start with explainable methods before
  introducing more advanced time-series techniques (Section 19).
- Forecasts are estimates, not guarantees — the report's own caveat is
  echoed in the Business Insights tab.
