# Website Analytics & Conversion Rate Optimization — Working Project

A simple, working implementation of the Week 4 strategy report
`Website Analytics and Conversion Rate Optimization`. Same lightweight
stack as Weeks 1-3, on purpose:

- **CSV file** as the data store (`data/website_sessions.csv`)
- **Pandas** for cleaning, KPI calculation and funnel/segment aggregation
- **NumPy** for the underlying calculations
- **Matplotlib** for every chart
- **Streamlit** for the interactive dashboard

No database, no analytics SDKs — a **simulated** session-level dataset
is generated locally, exactly as the report recommends for a student
analytical exercise (Section 2 & 7).

> **Note on structure:** the report's Appendix A suggests a flat layout
> (`week4_website_analytics.py`, `app.py`). This project uses a
> `data/` + `src/` layout instead, matching the pattern already used in
> the Week 1-3 projects in this internship series, so all four weeks
> stay consistent if combined into one repository.

## Setup

```bash
# 1. clone the repo
git clone https://github.com/<your-username>/website-analytics-cro.git
cd website-analytics-cro

# 2. create a virtual environment (optional but recommended)
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate

# 3. install dependencies
pip install -r requirements.txt

# 4. (re)generate the sample data — already included, but you can
#    regenerate a fresh simulated dataset any time
python data/generate_website_data.py

# 5. run the dashboard
streamlit run app.py
```

Then open the URL Streamlit prints (usually `http://localhost:8501`).

## How the funnel works

Each simulated session walks through:

```
Session → Landing Engagement (not bounced) → Product View
→ Add to Cart → Checkout Started → Payment Completed
```

Traffic sources and device types are given different underlying
"quality" multipliers when the data is generated (e.g. Social Media
has high traffic but lower intent; Mobile converts lower than
Desktop) — mirroring the exact patterns described in Sections 8 and 9
of the report. The dashboard then *rediscovers* those patterns from
the raw session data, the same way a real analysis would.

## Using your own data

Replace `data/website_sessions.csv` with a real (or anonymized) event
export using the same columns:

```
session_id, session_date, traffic_source, device_type, landing_page,
session_duration_seconds, pages_viewed, bounced, product_view,
added_to_cart, checkout_started, payment_completed, revenue
```

Everything downstream (KPIs, funnel, traffic/device/page breakdowns,
hypotheses) recalculates automatically.

## Notes

- All data is **synthetic**, generated by `data/generate_website_data.py`
  — safe to share publicly, no real visitor or customer data (Section 20).
- Hypotheses in the dashboard are computed from the data rather than
  hard-coded conclusions — they can come back unsupported if the
  underlying numbers don't back them up.
- This project focuses on descriptive/diagnostic analytics. A/B testing
  itself (Section 17) is intentionally out of scope — the dashboard is
  meant to help identify *where* to test, not to run the test.
