# Pricing Strategy A/B Testing — Working Project

A simple, working implementation of the Week 5 strategy report
`Evaluating Pricing Strategies Through A/B Testing Analysis`. Same
lightweight stack as Weeks 1-4, on purpose:

- **CSV file** as the data store (`data/pricing_experiment.csv`)
- **Pandas** for cleaning and group aggregation
- **NumPy** (+ the standard-library `math.erf`) for the statistical
  tests — a two-proportion z-test and Welch's t-test, computed from
  first principles instead of adding SciPy/Statsmodels as a dependency
- **Matplotlib** for every chart
- **Streamlit** for the interactive dashboard

No database, no statistics libraries — a **simulated** 40,000-visitor,
4-group pricing experiment is generated locally, exactly matching the
scenario described in Section 7 of the report.

> **Note on statistics:** the report suggests SciPy or Statsmodels for
> hypothesis testing. At the sample sizes used here (~10,000 per
> group), the normal approximation implemented directly with NumPy is
> effectively identical to what those libraries would return, so this
> project skips the extra dependency to keep the stack minimal, as
> requested.

| 11. Data Requirements | `src/pricing_analysis.py -> load_experiment()`, `clean_experiment()` |

## Setup

```bash
# 1. clone the repo
git clone https://github.com/<your-username>/pricing-ab-testing.git
cd pricing-ab-testing

# 2. create a virtual environment (optional but recommended)
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate

# 3. install dependencies
pip install -r requirements.txt

# 4. (re)generate the sample data — already included, but you can
#    regenerate a fresh simulated dataset any time
python data/generate_pricing_experiment_data.py

# 5. run the dashboard
streamlit run app.py
```

Then open the URL Streamlit prints (usually `http://localhost:8501`).

## The experiment

Four groups of 10,000 simulated visitors each:

| Group | Price | Idea being tested |
|---|---|---|
| Control | ₹1,000 | Current price |
| Moderate Discount | ₹850 | Lower price to drive more conversions |
| Premium | ₹1,300 | Higher price, fewer but bigger orders |
| Value Offer | ₹950 | Slight discount + perceived extra value |

The dashboard computes conversion rate, revenue per visitor, average
order value, units per order, and estimated profit per visitor for
each group, tests each treatment against Control for statistical
significance, and produces a recommendation based on profit — not
just whichever group converted the most, matching the report's core
argument in Section 13.

## Using your own data

Replace `data/pricing_experiment.csv` with a real (or anonymized)
experiment export using the same columns:

```
visitor_id, experiment_group, price_shown, visit_date, device_type,
traffic_source, converted, quantity, revenue, discount_amount, unit_cost
```

Everything downstream (KPIs, significance tests, recommendation)
recalculates automatically.

## Notes

- All data is **synthetic**, generated by
  `data/generate_pricing_experiment_data.py` — safe to share publicly.
- Statistical results are computed directly from the data, not
  hard-coded — a treatment that isn't actually different from Control
  will correctly show up as not significant.
- This project stops at analysis and recommendation. Actually running
  a live pricing experiment involves additional considerations (legal,
  customer fairness, technical rollout) noted in Section 12 of the
  report but out of scope for this internship deliverable.
